# Internationalization (i18n) Guide

This project uses `i18next` and `react-i18next` for robust localization support with runtime language switching, persistence, and RTL support.

## Features

- ✅ Runtime language switching without page reload
- ✅ Persistent language selection in localStorage
- ✅ Automatic RTL support with proper HTML attributes
- ✅ Async loading of language bundles (performance optimization)
- ✅ Fallback to English for missing translations
- ✅ Browser language detection
- ✅ Namespace support for organizing translations
- ✅ TypeScript support
- ✅ Number, date, and currency formatting utilities

## Usage Examples

### Basic Translation

```tsx
import { useTranslation } from 'react-i18next';

const MyComponent = () => {
  const { t } = useTranslation();
  
  return (
    <div>
      <h1>{t('welcome')}</h1>
      <p>{t('hello')}</p>
    </div>
  );
};
```

### Interpolation

```tsx
const { t } = useTranslation();

// In your JSX:
<p>{t('welcome_user', { name: 'Ahmed' })}</p>
// Outputs: "Welcome, Ahmed!" (English) or "أهلا وسهلا، Ahmed!" (Arabic)
```

### Pluralization

```tsx
const { t } = useTranslation();

// In your JSX:
<p>{t('items', { count: 5 })}</p>
// Outputs: "5 items" (English) or "5 عناصر" (Arabic)
```

### Using Direction Hooks

```tsx
import { useDir, useIsRTL } from '@/hooks/useDir';

const MyComponent = () => {
  const dir = useDir(); // 'ltr' or 'rtl'
  const isRTL = useIsRTL(); // boolean
  
  return (
    <div className={`text-${dir === 'rtl' ? 'right' : 'left'}`}>
      {isRTL ? 'This is RTL text' : 'This is LTR text'}
    </div>
  );
};
```

### Number and Date Formatting

```tsx
import { formatCurrency, formatDate } from '@/utils/intl';
import { useTranslation } from 'react-i18next';

const MyComponent = () => {
  const { i18n } = useTranslation();
  
  const price = formatCurrency(1500.75, i18n.language, 'USD');
  const date = formatDate(new Date(), i18n.language);
  
  return (
    <div>
      <p>Price: {price}</p>
      <p>Date: {date}</p>
    </div>
  );
};
```

### Language Switcher

```tsx
import LanguageSwitcher from '@/components/LanguageSwitcher';

const Header = () => {
  return (

      <LanguageSwitcher 
        variant="outline" 
        size="sm" 
        showFlag={true}
        showLabel={false}
      />
    </header>
  );
};
```

## Adding a New Language

Follow these steps to add support for a new language:

### 1. Create Translation Files

Create a new directory under `src/locales/` with your language code:

```bash
mkdir src/locales/fr
```

Add translation files (start with `common.json`):

```json
// src/locales/fr/common.json
{
  "hello": "Bonjour",
  "welcome": "Bienvenue",
  "welcome_user": "Bienvenue, {{name}}!",
  "items": "{{count}} élément",
  "items_plural": "{{count}} éléments"
}
```

### 2. Register the Language

Add the language to the registry in `src/i18n/languages.ts`:

```tsx
export const languages: Language[] = [
  {
    code: 'en',
    label: 'English',
    dir: 'ltr',
    flag: '🇺🇸'
  },
  {
    code: 'ar',
    label: 'العربية',
    dir: 'rtl',
    flag: '🇸🇦'
  },
  {
    code: 'fr', // Add your new language
    label: 'Français',
    dir: 'ltr',
    flag: '🇫🇷'
  }
];
```

### 3. Test the Language

The language will automatically appear in the language switcher and be available for selection.

## Adding New Namespaces

To organize translations better, you can add additional namespaces:

### 1. Create Namespace Files

```bash
# Add auth.json to each language
src/locales/en/auth.json
src/locales/ar/auth.json
```

### 2. Update i18n Configuration

In `src/i18n/i18n.ts`, add the namespace:

```tsx
// Add to the ns array
ns: ['common', 'auth'],
```

### 3. Use the Namespace

```tsx
const { t } = useTranslation('auth'); // Specify namespace
// or
const { t } = useTranslation(['common', 'auth']); // Multiple namespaces
```

## Configuration

### Language Detection Priority

The system detects language in this order:

1. **localStorage** (`housing_language` key)
2. **Browser language** (`navigator.language`)
3. **Fallback** (English)

### HTML Attributes

The system automatically updates:
- `<html lang="...">` attribute
- `<html dir="...">` attribute (for RTL support)
- Body classes (`rtl`/`ltr`)

### Performance

- Language bundles are loaded asynchronously only when needed
- Unused languages are tree-shaken from the bundle
- Vite's dynamic imports ensure optimal loading

## RTL Support

### Automatic Behavior

- HTML `dir` attribute is set automatically
- Body classes are added for CSS targeting
- Language switcher shows RTL badge for RTL languages

### CSS Considerations

Use logical properties in your CSS for better RTL support:

```css
/* Good - uses logical properties */
.element {
  margin-inline-start: 1rem;
  padding-inline-end: 0.5rem;
}

/* Better - use Tailwind's RTL-aware classes */
.element {
  @apply ms-4 pe-2; /* margin-start, padding-end */
}
```

## Best Practices

1. **Always use translation keys** instead of hardcoded strings
2. **Organize translations** into logical namespaces
3. **Provide fallback content** for missing translations
4. **Use interpolation** for dynamic content
5. **Test RTL layouts** when adding RTL languages
6. **Keep translation keys descriptive** but concise
7. **Use pluralization** for count-dependent text

## Troubleshooting

### Missing Translations

If a translation is missing, the system will:
1. Try to load from the fallback language (English)
2. Display the translation key as fallback
3. Log a warning in development mode

### RTL Issues

If RTL layout looks broken:
1. Check that logical CSS properties are used
2. Verify Tailwind classes are RTL-aware
3. Test with `useDir()` hook for conditional styling

### Performance Issues

If language switching is slow:
1. Check that translations are being cached
2. Verify dynamic imports are working
3. Use browser dev tools to check network requests
